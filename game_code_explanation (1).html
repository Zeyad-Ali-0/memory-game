⚡ Core AVR Concepts (Read This First)
DDR, PORT, and PIN — The Three Registers

Every physical pin on the ATmega328 (the chip inside an Arduino) is controlled by three 8-bit hardware registers. You choose a register by picking the correct letter (B, C, or D for the three ports).

DDR Data Direction Register
Sets the direction. Write 1 to a bit → that pin becomes an output. Write 0 → it becomes an input.
PORT Data Register
If the pin is an output: write 1 = HIGH (LED on), write 0 = LOW (LED off).
If the pin is an input: write 1 = enable the internal pull-up resistor.
PIN Input Register
Read only. Reading this tells you the current state of the physical pin. If a button is pressed (pulls it to GND), the bit reads 0. If released (pull-up holds it HIGH), the bit reads 1.
Why is pressed = 0 (LOW)?
Because of the input pull-up configuration. The internal pull-up resistor holds the pin at 3.3–5V (HIGH = 1) by default. When you press a button wired to GND, it pulls the pin to 0V (LOW = 0). So: 0 = pressed, 1 = released.
Bit Manipulation
REG |= (1 << n)
Sets bit n to 1 without touching any other bits. Used to turn an LED ON or set a pin to output.
REG &= ~(1 << n)
Clears bit n to 0 without touching any other bits. Used to turn an LED OFF or set a pin to input.
(REG & (1 << n)) == 0
Checks if bit n is 0 (button pressed in pull-up config). The & masks all other bits away so only bit n remains.
Example: If n=2, then (1 << 2) = 00000100. ANDing with PIND isolates only pin 2. If the result is 0, pin 2 is LOW = button pressed.

Each LED stays lit for 500 ms during sequences. Also used for the startup blink animation.

If a player takes more than 15 seconds without finishing, the round is automatically ended. Used in modes 2 and 3.

After detecting a button press, the code waits 30 ms and re-checks. This ignores the electrical noise ("bouncing") that mechanical buttons produce when they make/break contact.

Direction register for Port B. Player 2's pins will be set to input here.

Read register for Port B. Used to detect Player 2 button presses.

Total buttons in the game (4 per player × 2 players). Defined for reference but most loops use NUM_OF_BTNS_PER_PLAYER.

#define LED_ARRAY {0, 1, 2, 3}
The 4 LEDs use Port C, bits 0–3, which are Arduino's analog pins A0–A3. They're used as digital outputs here.
#define LED_DDR DDRC
Direction register for Port C. Setting bits here to 1 makes the LED pins outputs.
#define LED_PORT PORTC
Output register for Port C. Writing 1 to a bit turns the corresponding LED on; writing 0 turns it off.

Read register for Port C. Defined for completeness — LEDs are output-only, so this register isn't read in this project.

LOOP void loop() — runs forever, state machine

The Arduino framework calls loop() repeatedly and forever. Instead of a complex chain of conditions, a switch-case state machine keeps the code clean — each case handles one mode and then returns to the menu.

switch (currentState) { ... }
Reads currentState and jumps to the matching case. When the player picks a mode from the menu, currentState is set to 1, 2, or 3, so on the very next call to loop() the correct case executes.
case 0: menuFunction(); break;
Default state. Shows the menu and waits for a button. break exits the switch statement and loop() returns, then Arduino immediately calls loop() again — so menuFunction() is called over and over until the player presses something.
case 1:
pass = 0; fail = 0; totalTime = 0;
difficulty_level = DIFFICULTY_LEVEL;
playmode1();
currentState = 0;
break;
Solo Mode. Variables are reset first (so starting a new game doesn't carry over old scores). Then playmode1() runs its own internal loop for all 5 rounds. When it returns, currentState is set back to 0 (menu), and break exits the switch. Next call to loop() goes back to the menu.
break vs return — why this matters:
break exits only the nearest enclosing switch or loop. Here it exits the switch, loop() finishes, and Arduino calls loop() again immediately.
return would exit the function (loop()) itself — same effect here, but semantically different. Inside playmode1(), a break exits that function's inner loop, not the outer switch in loop().
case 2: ... playmode2(); currentState=0; break;
case 3: ... runChallengerMode(); currentState=0; break;
Same pattern as case 1. Each mode resets its scores, runs its full game, then hands control back to the menu.
default: currentState = 0; break;
Safety net. If currentState ever gets a value that isn't 0–3 (e.g. memory corruption), this resets it to menu. Prevents the game from being stuck in an undefined state.
keypad.ino
Button initialization and reading — input pull-up, debounce, press detection
INIT intializeKeypad() — Player 1 buttons (Port D)
void intializeKeypad() {
  for (int i = 0; i < NUM_OF_BTNS_PER_PLAYER; i++) {
    BTN_DDR  &= ~(1 << btns1[i]);   // set as INPUT
    BTN_PORT |=  (1 << btns1[i]);   // enable PULL-UP
  }
}
int btns1[] = BTN_ARRAY_ONE;
Expands to {2, 3, 4, 5} — the 4 bit positions in Port D for Player 1's buttons.
for (int i = 0; i < NUM_OF_BTNS_PER_PLAYER; i++)
Loops i = 0, 1, 2, 3 — one iteration per button. This way you don't have to write the same register operation 4 times.
BTN_DDR &= ~(1 << btns1[i]);
DDR Sets pin as INPUT. (1 << btns1[i]) creates a mask with only bit i set. ~ inverts it (all 1s except bit i). &= clears that bit in DDRD. A 0 in DDR = input direction.
BTN_PORT |= (1 << btns1[i]);
PORT Enables the internal pull-up resistor. Writing 1 to a pin that is already set as input activates the pull-up. This holds the pin at ~5V (HIGH/1) when the button is open, so pressing the button (connecting to GND) is clearly detected as 0.
Why pull-up? Without a pull-up, an unconnected (floating) input pin reads random noise — sometimes 0, sometimes 1. The pull-up gives it a definite known state: HIGH when not pressed, LOW when pressed.
READ getButtonPressed() — Player 1
int getButtonPressed() {
  for (int i = 0; i < NUM_OF_BTNS_PER_PLAYER; i++) {
    if ((BTN_PIN & (1 << btns1[i])) == 0) {   // pin reads LOW = pressed
      _delay_ms(DEBOUNCE_TIME);                 // wait 30ms
      if ((BTN_PIN & (1 << btns1[i])) == 0) { // still pressed?
        return i;                               // return button index 0-3
      }
    }
  }
  p1Released = true;
  return -1;   // nothing pressed
}
(BTN_PIN & (1 << btns1[i])) == 0
PIN Reads the physical state of pin btns1[i]. The & masks away all other bits. If the result is 0, that pin is LOW = button is pressed (pull-up means pressed = 0).
_delay_ms(DEBOUNCE_TIME);
if (...) == 0) { return i; }
Two-stage debounce: detect → wait 30ms → confirm. If the pin is still LOW after 30ms, the press is genuine (not bounce). Only then does it return the button index.
p1Released = true;
return -1;
If no button was pressed in the loop, mark Player 1 as released (used by modes that need to track button state across frames) and return -1 as a sentinel meaning "no button pressed".
Return value convention: Returns the index (0–3) of the button pressed, or -1 for none. Callers check for != -1 to know if something was pressed.
leds.ino
LED initialization and control via Port C
INIT initializeLEDs()
static const int LED_PINS[] = LED_ARRAY;  // {0, 1, 2, 3}

void initializeLEDs() {
  for (int i = 0; i < NUM_OF_LEDS; i++) {
    LED_DDR  |=  (1 << LED_PINS[i]);   // set as OUTPUT
    LED_PORT &= ~(1 << LED_PINS[i]);   // start LOW (off)
  }
}
static const int LED_PINS[] = LED_ARRAY;
static means this array lives in memory for the whole program (not recreated each function call). const means it can't be modified. Expands to {0, 1, 2, 3} for Port C bits 0–3.
LED_DDR |= (1 << LED_PINS[i]);
DDR Sets pin as OUTPUT. OR-ing 1 into the DDR bit makes the pin an output. Opposite of buttons — LEDs are outputs, buttons are inputs.
LED_PORT &= ~(1 << LED_PINS[i]);
PORT Ensures LED starts OFF. Clears the PORT bit so the pin outputs LOW (0V). The LED receives no current → is off at startup.
CONTROL turnOnAll / turnOffAll / turnOnRandomLED
LED_PORT |= (1 << LED_PINS[i]);
Turn ON: Sets the PORT bit to 1 → pin outputs ~5V → current flows through LED → LED lights up.
LED_PORT &= ~(1 << LED_PINS[i]);
Turn OFF: Clears the PORT bit to 0 → pin outputs 0V → no current → LED off.
int l = random(NUM_OF_LEDS);
turnOffAll();
LED_PORT |= (1 << LED_PINS[l]);
return l;
Random LED: Picks a random index 0–3, turns all LEDs off first (clean state), then turns on only the chosen one. Returns the index so the game knows which LED was lit (to compare with the player's button press).

Moves the cursor to column 3 (right after "P1:") and prints the current p1Score, then does the same at column 13 for p2Score. The space after the number (lcd.print(" ")) overwrites old digits (e.g. if score goes from 10 to 9, the trailing space clears the extra digit).

menu.ino
Mode selection screen — displays options, reads P1 button, sets currentState
FLOW menuFunction()
extern int currentState;
References the global state variable from main_file.ino. This function is the only place that changes currentState based on player input.
lcd.setCursor(0,0); lcd.print("1:Solo 2:Duel ");
lcd.setCursor(0,1); lcd.print("3:Challenger ");
Displays the menu every time this function is called (i.e., every call to loop() while in state 0). This is intentional — the LCD might need redrawing after returning from a mode.
int btn = getButtonPressed();

if (btn == 0) currentState = 1;

mode_1.ino — Solo Mode
Single-player Simon Says: watch the LED sequence, repeat it with buttons
LOOP Main game loop
while (pass + fail < NUM_OF_ITERATIONS) {
  ...
}
while (pass + fail < NUM_OF_ITERATIONS)
The game runs until the player has completed 5 rounds total (pass + fail = 5). Whether you win or lose a round, it counts. The while loop keeps the game going until all rounds are done.
long start_t = millis();
Records the timestamp (in ms since power-on) at the start of each round. Used later to compute how long the player took to answer.
PHASE 1 Generate and show LED sequence
for (i = 0; i < difficulty_level; i++)
LED_Sequance[i] = random(NUM_OF_LEDS);
Fills the sequence array with difficulty_level random numbers (0–3), each representing one of the 4 LEDs. The array is used twice: once to show the player, once to check their input.
for (i = 0; i < difficulty_level; i++) {
LED_PORT |= (1 << LED_Sequance[i]);
_delay_ms(BlinkTime);
turnOffAll();
_delay_ms(400);
}
Shows each LED in the sequence for 500ms, then turns all off for 400ms before the next. The 400ms gap makes each step visually distinct so the player can count them.
PHASE 2 Collect player input
while (getButtonPressed() != -1) { _delay_ms(10); }
Wait for release before each step. If the player is still holding from the previous input, this loop spins until they let go. Prevents one hold registering as multiple presses.
while (btn == -1) { btn = getButtonPressed(); }
Wait for a press. Spins doing nothing until the player presses a button. When a button is pressed, getButtonPressed() returns 0–3 and the inner loop exits.
if (btn != LED_Sequance[i]) {
difficulty_level = DIFFICULTY_LEVEL;
fail++; break;
}
Wrong button: resets difficulty back to 3 (you lose your streak), increments fail, and break exits the input-collection for-loop immediately. The outer while loop sees fail++ and continues to the next round.
if (i == difficulty_level) { ... pass++; difficulty_level++; }
All correct: After the for-loop, if i reached difficulty_level without a break, all answers were correct. pass++ records the win. difficulty_level++ makes the next round one step longer.
The break/i trick: The for-loop variable i is declared outside the loop (int i; at the top of the function). If a break happens mid-loop, i is less than difficulty_level. If no break, i == difficulty_level means all steps were correct. This is how the code detects success vs failure without a separate boolean flag.
END Summary and return
loop_LCD_SCREEN_mode1();
delay(3000);
// returns here
After the while loop ends (5 rounds done), shows the pass/fail summary on the LCD for 3 seconds. Then playmode1() simply returns — execution goes back to case 1: in main loop(), which sets currentState = 0 and breaks → menu.
mode_2.ino — Duel Mode
Two players race to enter the same LED sequence simultaneously
CONCEPT How Duel works

Both players see the same LED sequence. Then both start entering it at the same time. The first to finish the full correct sequence wins the round. If either player presses the wrong button, they are eliminated from that round. The game tracks time to break ties when both finish correctly.

LOOP Outer round loop
int difficulty_level = DIFFICULTY_LEVEL;
int rounds = 0;
These are local variables, not the global ones from main_file. Mode 2 manages its own difficulty independently. Rounds count from 0 to NUM_OF_ITERATIONS-1.
while (rounds < NUM_OF_ITERATIONS)
Runs exactly 5 rounds. Unlike Mode 1 which ends when pass+fail=5, here rounds is always incremented at the end of every round, so exactly 5 always happen.
CONCURRENT INPUT The simultaneous input loop
while (true) {
  if (millis() - startTime >= ROUND_TIMEOUT) break; // timeout
  int btn1 = getButtonPressed();
  int btn2 = getPlayer2Button();
  ...
  if (p1Finished || p2Finished) break;
  if (p1Eliminated && p2Eliminated) break;
}
while (true)
Infinite loop that only exits via break. This is the core of the concurrent input system — it keeps polling both players on every iteration until an exit condition is met.
if (millis() - startTime >= ROUND_TIMEOUT) break;
Timeout safety. If 15 seconds pass without a winner, the round ends automatically. millis() returns ms since startup; subtracting the start time gives elapsed time for this round.
bool released1 = true;
bool released2 = true;
Button release trackers, initialized before the concurrent loop. When a button is released (btn == -1), released is set to true. A new press is only processed if the button was previously released — prevents holding a button to spam inputs.
if (!p1Eliminated && !p1Finished && btn1 != -1 && released1) {
released1 = false;
if (btn1 == LED_Sequence[i1]) { i1++; ... }
else { p1Eliminated = true; }
}
Player 1 input block. Four conditions must all be true: player not eliminated, not finished, a button is pressed, and it's a fresh press (not a hold). If correct, i1 advances. If wrong, player is eliminated for this round. Same logic exists for Player 2 with i2 and p2Eliminated.
if (i1 == difficulty_level) { p1Finished = true; p1FinishTime = now - startTime; }
When a player's index reaches the sequence length, they've completed all steps correctly. Their finish time is recorded (elapsed ms) so it can be compared if both finish.
if (p1Finished || p2Finished) break;
if (p1Eliminated && p2Eliminated) break;
Exit conditions: if anyone finishes, stop immediately (no need to wait for the other). If both are eliminated, also stop (no winner possible).
RESULT Determining the winner
if (p1Finished && p2Finished) {
if (p1FinishTime < p2FinishTime) p1Score++;
else if p2FinishTime < p1FinishTime) p2Score++;
else result = "Dead Tie!";
}
If both finished, the faster one wins (compared in milliseconds). A tie is possible but rare. If only one finished, they win the round unconditionally.
if (p1Finished || p2Finished) difficulty_level++;
else difficulty_level = DIFFICULTY_LEVEL;
Difficulty increases only if someone actually finished the sequence. If both were eliminated or timed out (no winner), difficulty resets to keep the game fair.
mode_3.ino — Challenger Mode
Turn-based: one player sets the sequence, the other must replicate it
CONCEPT How Challenger works

Players alternate being the Challenger (sets the secret sequence) and the Defender (tries to replicate it). If the Defender succeeds → Defender gets a point. If they fail → the Challenger must prove they can do it themselves. If the Challenger also fails → no points (you can't lie). Roles swap every round.

HELPER getActivePlayerButton()
static int getActivePlayerButton(int playerNum) {
if (playerNum == 1) { ... BTN_PIN ... }
else { ... BTN_2_PIN ... }
}
A unified button reader. Takes a player number (1 or 2) and reads the correct PIN register. This avoids code duplication — instead of two separate functions for each player, one function handles both based on the argument.
static
static on a function limits its visibility to this file only (file-scope). It's a safety measure — other .ino files can't accidentally call this internal helper.
if (!(BTN_PIN & (1 << btns[i]))) return i;
The ! inverts the result of the bit-AND. If the pin is 0 (pressed), the AND result is 0, which is falsy, and ! makes it true → return that button index. Equivalent to == 0 check but slightly more compact.
FUNCTION enterSequence() — Challenger sets the code
static int secretSequence[DIFFICULTY_LEVEL];
A file-scope static array. Stores the sequence the Challenger presses. static here means it persists across function calls (it's not on the stack). Both enterSequence and replicateSequence use it.
for (int i = 0; i < DIFFICULTY_LEVEL; i++) {
int btn = -1;
while (btn == -1) { btn = getActivePlayerButton(playerNum); }
secretSequence[i] = btn;
LED_PORT |= (1 << btn); _delay_ms(300); turnOffAll();
waitForPlayerRelease(playerNum);
}
For each step: wait for the challenger to press a button, store it in secretSequence, flash the corresponding LED (feedback), then wait for release before accepting the next press. This prevents one long press from filling multiple slots.
FUNCTION replicateSequence() — Defender tries to copy
static bool replicateSequence(int playerNum)
Returns true if successful, false if wrong or timed out. The bool return is how the caller (runChallengerMode) knows who gets the point.
if (millis() - startTime >= ROUND_TIMEOUT) return false;
Timeout check inside the button-wait loop. If 15 seconds pass, returns false immediately — no partial credit for getting some steps right.
if (btn != secretSequence[i]) return false;
Wrong button at any step → immediately return false. There's no recovery; you must get the entire sequence perfectly.
return true;
Only reached if the for-loop completes without any early return — all steps were correct. The caller awards a point to this player.
MAIN runChallengerMode() — round management
bool p1IsChallenger = true;
Tracks whose turn it is to be the Challenger. Starts as Player 1 on round 1. Toggled with p1IsChallenger = !p1IsChallenger after every round.
int challenger = p1IsChallenger ? 1 : 2;
int defender = p1IsChallenger ? 2 : 1;
Derives the actual player numbers from the boolean flag. Ternary operator: if p1IsChallenger is true → challenger=1, defender=2. Next round they swap.
enterSequence(challenger);
Challenger presses their secret sequence. The sequence is saved in secretSequence[].
// Flash the sequence for the defender to watch
for (int i = 0; i < DIFFICULTY_LEVEL; i++) {
LED_PORT |= (1 << secretSequence[i]);
_delay_ms(BlinkTime);
turnOffAll(); _delay_ms(200);
}
After the Challenger enters the sequence, it's replayed on the LEDs so the Defender can memorize it. The Defender watches, not presses.
if (replicateSequence(defender)) {
// defender scores
} else {
// challenger must prove it
if (replicateSequence(challenger)) { // challenger scores }
else { // liar! no points }
}
The complete scoring logic: Defender succeeds → Defender gets a point. Defender fails → Challenger must prove they CAN do it. Challenger proves it → Challenger gets the point (they set a valid challenge). Challenger also fails → no points (the sequence was impossible or forgotten).
p1IsChallenger = !p1IsChallenger;
Flips the boolean: true → false → true. This swaps roles every round so both players spend equal time as Challenger and Defender over 5 rounds.
